NODE E FNM NELLA PROPRIA UTENZA - WINDOWS X64

1. Estrai tutto lo ZIP in una cartella, ad esempio sul Desktop.
2. Avvia INSTALLA.cmd con un doppio clic, senza Esegui come amministratore.
3. Attendi il download e l'installazione. La finestra deve indicare
   Installazione completata e mostrare fnm 1.39.0, Node v24.22.2 e npm.
4. Chiudi tutte le finestre di Visual Studio Code.
5. Avvia Apri-terminale-Node.cmd: inizializza fnm e chiede quale cartella aprire.
6. Seleziona MC-Progetto, MC-Demo oppure Strumento (con bin e lib),
   secondo il punto della configurazione a cui sei arrivato.
   Il terminale si posiziona nella cartella scelta e apre VS Code su quel
   percorso esplicito, se il comando code.cmd e disponibile.
   Se annulli la scelta, non viene aperta alcuna cartella.
   Se VS Code non e nel PATH, aprilo e usa File > Open Folder per scegliere
   la stessa cartella. Windows e le sue sottocartelle vengono rifiutati.

7. Nel nuovo VS Code, Terminale > Nuovo terminale > Prompt dei comandi.
   Controlla node --version e fnm --version. Node deve essere v24.22.2.
   Per npm su Windows usa npm.cmd se PowerShell blocca il file npm.ps1.
   Esempio nel progetto: npm.cmd run mc -- import esportazione.json

DOVE INSTALLA

%LOCALAPPDATA%\MC-Code-Tools\fnm

Node viene estratto nella cartella node-versions\v24.22.2\installation
di fnm. Il comando fnm default registra questa versione come predefinita.
Il download e l'estrazione usano PowerShell e i certificati di Windows.
Non serve scaricare nuovamente Node attraverso fnm durante questa procedura.
Per aggiornamenti successivi puoi usare fnm install e fnm default
dal terminale inizializzato, secondo i permessi di rete aziendali.

La procedura imposta FNM_DIR e aggiunge fnm e il suo alias default al PATH
della sola utenza. Il PATH precedente viene salvato sotto MC-Code-Tools.
Se esiste un FNM_DIR utente diverso, si ferma conservando la configurazione.
Un'installazione ripetuta non elimina le versioni Node gia presenti.
Non installa nvm e non modifica profili PowerShell, ExecutionPolicy,
impostazioni di sistema o regole aziendali.

Per usare fnm use in un PowerShell aperto normalmente, inizializza prima:

fnm env --shell powershell | Out-String | Invoke-Expression

In alternativa usa sempre Apri-terminale-Node.cmd.
Se una vecchia procedura ha aperto System32, usa File > Open Folder
e seleziona la cartella del tuo progetto. Il punto in code.cmd . indica
la cartella corrente, quindi non usarlo da un terminale in System32.

Una sessione gia aperta di VS Code puo mantenere il vecchio ambiente:
chiudila completamente prima di avviarla dal terminale Node.
